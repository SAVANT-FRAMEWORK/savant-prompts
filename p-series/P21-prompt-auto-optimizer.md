# P21: Prompt Auto-Optimizer

P21 is the self-improving-prompt module of the SAVANT FRAMEWORK operations registry and the opening module of the Meta-Cognitive tier (P21–P25). Its end-state objective is prompts that improve themselves while you sleep: an evolutionary loop in which candidate prompt variants are generated by defined mutation operators, tested against a fixed evaluation dataset, selected on measured fitness, and promoted to production under monitoring. Human prompt engineering shifts from manual iteration to supervising the loop — defining the baseline, curating the evaluation set, and reading the results — while the search itself runs on a schedule.

## Methodology

### Deployment Sequence

1. **Define the baseline prompt and evaluation dataset.** The evaluation set is the fixed yardstick for all candidates; evolutionary search against a moving or unrepresentative dataset optimizes noise.
2. **Implement mutation operators.** Define the variation vocabulary — constraint changes, example swaps, and comparable structured edits — so variants explore the prompt space systematically rather than randomly.
3. **Run the evolution loop.** Iterate generate → test → select → repeat: variants are generated by mutation, scored against the evaluation dataset, and the fittest retained as parents of the next generation.
4. **Deploy the winner and monitor production metrics.** Promotion to production is followed by live monitoring, so evaluation-set fitness is confirmed against real traffic.
5. **Schedule recurring evolution runs.** The loop runs on a weekly cadence, so improvement is continuous rather than a one-time search.

### Deployment Artifacts

- `prompt_evolution_system` — the mutation operators, generation loop, and selection machinery.
- `evaluation_harness` — the fixed dataset and scoring pipeline against which all candidates are measured.

### Target Telemetry (registry-specified)

- **Prompt improvement rate:** approximately +5% accuracy per week in the initial phase.
- **Human prompt engineering time:** reduced by 80% as iteration shifts from manual to supervised.
- **Best-prompt fitness plateau:** improvement below 1% over three consecutive generations marks convergence and signals the search has exhausted the current mutation space.

## Merits

- **Search beats intuition in the tail of the prompt space.** The registry's reference scenario — a marketing copy generator — reports the system discovering that adding a "write for a skeptical reader" constraint improved conversion by 12%, an insight no human on the team had tested. Systematic mutation finds effective interventions outside the team's hypotheses.
- **Convergence is defined, not assumed.** The plateau criterion (under 1% improvement across three generations) gives the loop an explicit stopping signal, preventing both premature termination and indefinite compute spend on a converged search.
- **Evaluation discipline is structural.** Because all candidates face the same fixed dataset, fitness comparisons are meaningful across generations, and production monitoring closes the gap between benchmark fitness and live performance.
- **Labor reallocation with a measured figure.** The 80% reduction in manual prompt-engineering time converts an open-ended craft activity into a bounded supervision task.

## Guidance for Use

**When to deploy.** Deploy P21 once a prompt is in production with enough traffic to support meaningful evaluation, and when the marginal value of prompt quality justifies ongoing automated search — high-volume customer-facing generation, conversion-sensitive copy, and comparable workloads where single-digit accuracy or quality gains compound.

**Prerequisites.** A trustworthy evaluation dataset is the hard prerequisite; the loop amplifies whatever the dataset measures, including its biases and gaps. Production metric monitoring must exist before winners are promoted, so benchmark gains can be verified against live behavior. A baseline prompt that already works acceptably gives the search a sane starting point.

**Recommended pairings.** P21 consumes latency objectives from P17 (Performance Optimization Engineer) where prompt compression is a goal; its feedback signals align with P28 (Feedback Loop Architect), which generalizes learning-from-interaction beyond the prompt layer; and its deployed winners should pass the adversarial suite maintained under P20 (Prompt Security Guardian) before promotion, since a fitter prompt is not necessarily a more robust one.

**Misuse and limitations.** Do not run evolutionary search against an evaluation set that does not represent production distribution — the loop will faithfully optimize the wrong thing. Do not auto-promote winners in high-stakes domains without human review; a variant can gain benchmark fitness while acquiring undesirable behavior the metric does not capture. Treat the initial +5%-per-week improvement rate as an early-phase figure; the registry itself specifies that fitness plateaus, and continued runs after convergence yield diminishing returns.
